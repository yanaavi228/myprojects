# AGENTS.md — SQL Тренажёр

Интерактивный тренажёр SQL в браузере. Подробное описание для пользователей — в [README.md](README.md).
## Архитектура

- **Один файл — весь клиент**: [index.html](index.html) содержит разметку, CSS (в `<style>`) и весь JS (в `<script>`). Сборки, npm и фреймворков нет и не нужно — ванильный JS.
- [alasql.min.js](alasql.min.js) — вендорная библиотека AlaSQL (SQL-движок в браузере). *
- [server.ps1](server.ps1) — опциональный PowerShell-сервер (порт 8585): статика + JSON API `/api/ping`, `/api/auth`, `/api/sandbox`. Клиент работает и без него (тогда аккаунты локальные, в localStorage).
- `setup-hosting.ps1`, `share-public.ps1` — одноразовые скрипты хостинга (брандмауэр/автозапуск, туннель Cloudflare).

## Ключевые места в index.html

- `DB` — исходные данные учебной базы (4 таблицы). Используется для практики, уроков и как снапшот для песочниц.
- `tasks` — задачи практики, формат: `{title, desc, level, sol, hint}` (+ флаг `ai` у сгенерированных). Проверка — сравнение **результата**, а не текста запроса (`compare`/`norm`): числа округляются до 2 знаков, порядок строк важен, только если в эталоне есть `ORDER BY`.
- `LESSONS`, `LINKS` — уроки и карточки материалов.
- `TPL` + `localTask` — офлайн-генератор заданий по шаблонам (запасной вариант ИИ-конструктора).
- `callLLM` — цепочка ИИ-провайдеров: ключ Gemini/Groq/OpenAI-совм. → бесплатный Pollinations.ai. `BUILTIN_KEY` в начале скрипта — встроенный ключ для всех гостей.

## Соглашения

- **Язык интерфейса и контента пока что— русский.** 
- **Диалект SQL — AlaSQL**: без оконных функций, без CTE, без ILIKE. В практике и уроках разрешён только `SELECT` (проверка в `runSql`); изменение данных — только в песочнице.
- Псевдонимы столбцов в решениях — латиница snake_case, не зарезервированные слова SQL (см. `ALIAS_RULE`).
- Состояние клиента — localStorage с префиксом `sqlt-`: `sqlt-done` (решённые), `sqlt-ai` (настройки ИИ), `sqlt-ai-tasks` (сгенерированные задания), `sqlt-del` (названия удалённых задач — не показываем при загрузке), `sqlt-t-<логин>:<название>` (черновик запроса по задаче, у каждого аккаунта свой; у гостя черновики только в памяти), `sqlt-tasks-collapsed` (список задач свёрнут), `sqlt-quiz` (текущий тест), `sqlt-users`, `sqlt-session`, `sqlt-sb-<логин>`, `sqlt-draft-<id>` (черновики полей sbq/aiq/qask). Песочница хранится как лог запросов (макс. 300), воспроизводимый на копии `DB`.
- Песочница доступна только после входа (`canEdit`); гость видит приглашение войти — проверка в `renderSb` и обработчике `#sbrun`.
- Пароли — PBKDF2 (100 000 итераций, SHA-256); одинаковая схема на клиенте и в server.ps1 (`Get-HashPw`), при изменении держи их синхронными.
- В server.ps1 запись в `users.json` / `sb-*.json` защищена мьютексом `SQLTrainerUsers` — сохранять блокировку при правках.
